## Direction contract

**THESIS:** Make the display and its content the owner's working surface. Routine
content changes precede precision geometry and refresh engineering.

**OWN-WORLD:** Retain warm paper `#f5f4ef`, pale canvas `#eeeee7`, forest green
`#2f5745`, dark green ink and readable muted green. Quiet borders, restrained
rounding, native controls, local type and the real monochrome frame carry the
identity. Odd Orbit's original dark logo tile remains a modest maker signature.

**STORY:** Recognise the displayed state, enter a draft, select a component, edit
content and explicitly save. Connect information in Data sources; set quiet
hours in Device. Keep advanced controls available separately. Orbi appears on
About only.

**FIRST VIEWPORT:** Compact top navigation, Your display and save actions, large
canvas left, content inspector right, horizontally browsable component strip
below. Add component opens a source-grouped picker. Content/Position/Style tabs
keep the inspector legible. Focus, draft state and undo remain predictable.

**FORM:** Canvas + task dock, grounded structure 7. Prior surface round reference:
`seed:c31a67cdbd74cef9`. The owner's explicit choice supersedes the open round:
“Ok I like option A the best, and I like your suggestions for branding too. lets
do this work on a UIUX branch”. Option A and About-only Orbi were recommended
with the screenshots in `ui-ux-review-2026-11-15/`. This is a code-led build;
those screenshots are composition references, not pixel-exact image comps.

**FINISH:** unreviewed and undocumented is unfinished; this build ends with the
finish review, the verdict, DESIGN.md, and every shipping raster carrying its
provenance

## Behaviour and adaptations

Use familiar controls. No decorative entrance animation: responses to selection,
editing and expansion explain changes without moving the work away. Preserve
precise numeric editing, flow/positioned layouts, plugin settings and secrets.
Do not promise shared Google OAuth, JSON import, GitHub updates, automatic
physical display output or component design before placement in this work.

At narrower effective desktop widths, stack inspector below the canvas and
reflow data/settings forms. The two-dimensional display can scale or scroll;
surrounding navigation and controls must remain accessible. Full mobile editing
is not a release promise.

The real application's refresh diagnostics live in Device; the prototype's
workspace status is represented by the header's live service/display state.
Source forms reflect actual plugin schemas rather than fixed demonstration
fields. Preserve dirty drafts and account prerequisites through navigation.
