Update setup and recovery

Normal updates run from Device → Updates. Choose a release, review it, then confirm the restart. Save your layout changes first and keep power connected.

During an update

Paperphase checks the publisher and package before showing Updating on the physical screen. Display cooldowns still apply. The supervisor then backs up saved data, restarts the app and checks it is ready. Normal screen content resumes according to your saved quiet-hours settings.

The original browser tab follows supervisor progress while the app restarts. A failed startup restores the previous software and compatible saved data.

If recovery is needed

Use SSH to inspect the transaction. These commands match the example Pi installation; substitute your installation paths if different.

/home/pmck/paperphase-test/bootstrap/paperphase-update-agent status \
  --installation /home/pmck/paperphase-test/installation.json

If automatic rollback could not finish, stop the managed service before explicit recovery:

sudo systemctl stop paperphase.service
/home/pmck/paperphase-test/bootstrap/paperphase-update-agent recover \
  --installation /home/pmck/paperphase-test/installation.json
sudo systemctl start paperphase.service

Recovery retains the backup and failed-version data. If a backup or executable is unavailable, keep the files in place and use your known-good bootstrap binary and private-state backup.

Set up an existing development image

UI updates need the independent supervisor installed once. Factory images should already include it. The supervisor stays outside application release slots, stores trusted public publisher keys, and preserves the existing private data folder and host permissions. Publisher private keys never belong on a device image.
